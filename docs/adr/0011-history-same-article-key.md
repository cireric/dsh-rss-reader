# ADR-0011：回溯的同文键与跨源重复键不是一套口径

- 状态：已采纳（2026-11-23）
- 适用：`src/duplicates.ts` 的 `linkKeyOf` / `sameArticleKeyOf`；R9 的候选去重与「已存在就跳过」

## 背景

R9 要用「已订阅条目的链接形态」筛归档页，并用「这个 URL 是不是已经在库里」跳过重复。仓库里唯一的链接归一化是 `linkKeyOf`（跨源重复提示用），它明确把 `http` 与 `https` 视为不同文章——这是刻意的保守规则，不是遗漏。

实测（2026-11-23）：阮一峰 `atom.xml` 里的文章链接是 `http://www.ruanyifeng.com/blog/…`，而站点归档页给的是 `https://www.ruanyifeng.com/blog/…`。用 `linkKeyOf` 判重 ⇒ 归档页里最新的 3 篇会被当成新文章再抓、再入库一次，同一篇在列表里出现两次。

两个方向都有人会选：

- **改 `linkKeyOf` 全局忽略协议**：`link_key` 是**已存的派生列**，规则一改全库过期，要 v6 迁移重算；而且跨源重复提示会多出一类命中（可能对，但那是另一个产品决定）。
- **只在回溯里另写一套比较**：两套规则长期漂移，是仓库反复付学费的「同一判据两份实现」。

## 决定

1. `linkKeyOf` 不动。它的语义是「跨源重复提示的键」。
2. 新增 `sameArticleKeyOf(link)`：**与 `linkKeyOf` 同一条规则，唯一差别是去掉协议**；只用于 R9 的「这篇是不是已经在库里」。
3. 两者的关系写进代码注释与 `GLOSSARY.md`：`link_key` 回答「两个源是否在说同一篇」，`sameArticleKeyOf` 回答「这条链接是否已在**这个源**里」。不是一套口径，不许合并。
4. 回溯的判重范围限**同一订阅源**；跨源重复仍由 `link_key` + `duplicateHintsOf` 负责。

## 后果

- 回溯能识别 http/https 混用（样本 1 的直接收益：3 篇不重复抓）。
- 跨源重复提示保持原样；`link_key` 无迁移、无重算。
- 代价：两个长得很像的函数并存。缓解是 `sameArticleKeyOf` **由 `linkKeyOf` 派生实现**（不复制规则），并有一条单测钉住「两者只在协议上不同」。
- 若将来决定全局忽略协议，改动点是 `linkKeyOf` + 一次 v6 迁移，`sameArticleKeyOf` 可以随之删除——这条路留在这里，不是遗漏。
