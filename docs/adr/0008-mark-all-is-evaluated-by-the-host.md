# 0008 — A 的候选集由宿主按同一判据求值

- 状态：已接受（2026-11-21）
- 相关：ADR-0001（判据只有一个裁决者）、ADR-0005（显示窗只判 published_at）、ADR-0006（未读账跟随显示窗）

## 背景

「全部标为已读」（A）原先由客户端求值：`visible()` 在 `state.items` 上按范围与过滤筛，
再按 A 的范围阈值过滤。`state.items` 只是**已加载的几页**（每页 `maxItemsShown`，默认 300）。
而左栏角标来自宿主全量账目 `perFeedUnread`。

后果：一个源有 19 条未读、但已加载页里 0 条时，A 的候选是 0；用户必须反复点「加载更多」
把条目灌进客户端再按 A。实测（2026-11-21）：`{ Mario Zechner }` 0 → 15 → 19 三档。

## 决定

A 的候选集**定义**不变（范围 × 过滤 × 显示窗 × A 的范围 × 未读且非保持未读），但求值域改成
**宿主库全量**，并且求值只发生在宿主一处：

- `markRead` 接受范围（`feedId` / `folder` / `tagId`）或 `all: true`，宿主按同一条判据选 id；
- `dryRun: true` 只回条数（确认框的 N），不写库；
- 真正标读时宿主回 `{ changed, ids }`，`ids` 供客户端撤销；
- 搜索态仍走 `itemIds` 快照（搜索结果不是库的一个范围）。

## 后果

- 客户端不再需要「把全部页加载完」才能标全；确认框的 N 与真正标读共用宿主判据。
- 撤销仍按 id 集合，5 秒单槽语义不变；大批量时 payload 变大（本地通道，可接受）。
- 宿主多了一条「按范围遍历」的读路径：`listRecent` 500/页遍历到游标用尽（或越过 `before` 边界）。
- 源视图的**列表**仍只显示「全局页 ∩ 源」——本决定不修列表，只修 A 的求值（F1 另议）。
- 若将来加「按搜索条件标读」，需要另一条判据（搜索表达式），不走本决定的 scope。
