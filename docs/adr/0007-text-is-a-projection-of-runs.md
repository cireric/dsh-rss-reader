# ADR-0007：正文块的 `text` 是 `runs` 的派生投影

- 状态：已采纳（2026-11-21）
- 适用：`src/article.ts` 的块模型与抽取、`src/article-text.ts` 的纯文本投影、以及所有读 `text` / `items` 的地方

## 背景

R5 给正文块补内联语义（`runs`：普通文字 / 加粗 / 斜体 / 行内代码 / 链接）与表格块。于是每个带内联语义的块
同时有两个字段：`runs`（权威，渲染用）与 `text`（纯文本，搜索 / 时长 / 字符统计 / 日志 / agent 工具用）。

三条路摆在面前：

1. **只留 `runs`**，让七处消费者各自把 `runs` 摊平成纯文本。看似干净，实际是把「富文本怎么压成纯文本」
   这条规则复制七份，而且它们分布在**不同进程**（搜索在 worker 线程）与**不同层**（存储淘汰、Agent 工具）——
   下一次改这条规则，七处里漏一处不会有任何断言翻红。
2. **只留 `text`**，渲染期再从 `text` 反推内联语义。做不到：信息已经在抽取期丢了，这正是本项要修的问题。
3. **两个都留，且 `text` 由 `runs` 派生**（本 ADR）。

`htmlToText` 的存在让这件事变得更尖锐：它给每个标签塞一个空格，`"详见<a>官方文档</a>。"` 会变成
`"详见 官方文档 。"`。所以 `text` 一旦继续走 `htmlToText`、`runs` 走内联解析，两者**必然不等**——
不存在「两个都留但各算各的」这条中间路。

## 决定

1. **`runs` 是权威，`text` 是派生投影**：带 `runs` 的块，其 `text` 由 `runs.map(r => r.text).join('')` 得出。
   `list` 的 `items[i]` 由 `itemRuns[i]` 同理派生。
2. **不变量是严格相等**，不是「空白归一化后相等」：`runs.map(r => r.text).join('') === text`。
   为满足真实 HTML（`<p>` 内部几乎总有换行与缩进），**归一化发生在切 run 之前**——
   先把该块的可见文本收敛成单空格并 trim，再在归一化后的文本上切 run。顺序反了，严格相等就会红。
3. **纯文本投影只有一处实现**，住 `src/article-text.ts`（零 node 依赖）。它必须零 node 依赖，因为
   `shared.ts` 的 `estimateReadingMinutes` 会打进 client bundle，而 `article.ts` import 了 `node:crypto`
   与 `feed/fetch.js`。`article.ts` 对它做 re-export，既有 import 不破。
4. **`htmlToText` 不修**。它继续服务于「没有 runs 的路径」（`pre` 之外的旧缓存、R4 的回退摘要、列表行摘要）。
   它「标签→空格」的行为只在带 runs 的正文块上被绕开，不是被改掉。
5. **纯文本段落不产出 `runs`**。`runs` 缺席即「这段没有内联语义」，不必给每个段落塞一个 text run——
   那会让序列化体积无谓地翻倍，而额度闸门（可见字符）看不见。

## 后果

- `text` 从「抽取结果」变成「派生投影」。它仍然是必填字段，但**它不再有独立的生成路径**：
  谁把它改回 `htmlToText` 派生，不变量当场红。
- `EXTRACTOR_REVISION` 必须抬一次（块形状变了，旧缓存里没有 `runs`）。连带后果：旧文章首次打开重抓一次、
  单篇阅读进度重置一次、agent 的 `rss_read_article` 对旧缓存先报「已过期」。
- **实际磁盘占用会涨到可见字符的 2–6 倍，而额度计数（可见字符）不变**。这是有意的：额度语义是
  「这篇有多少可读内容」，改成字节数会让同一个用户看到的「释放约 X KB」与今天不一致，也会让额度占用
  随标签密度波动。守卫写成**结构判据**（run 数 ≤ 标签数 + 1、相邻同类 run 必须合并），不是比值上限 ——
  比值上限在算术上不成立：`text` 与 `runs` 各存一份同样的文字，最小 runs 形态实测已达 6.59。
- 顺带修好一个既存缺陷：`htmlToText` 的标签→空格让 `"详见 官方文档 。"` 在句子边界上搜不到；
  改由 runs 派生后 `"详见官方文档。"` 可以命中。这条要有用例钉住，否则下次有人「优化」回去时无人发现。

## 被拒绝的替代方案

- **只留 `runs`**（让七处各自摊平）：拒绝理由见「背景」第 1 条。
- **只留 `text`**：信息在抽取期就已丢失，本项要修的正是这个。
- **弱判据（归一化后相等）**：会让「`text` 里多一处空格」这类真实缺陷逃过判据，而空格恰恰是本仓库踩过的坑。
  把归一化提到切 run 之前，既满足真实 HTML，又不放弃严格相等。
